OBJECTIF UNIQUE DU PACK 1
Créer le socle Web autonome minimal de NYR afin que le projet puisse être ouvert localement sur PC et afficher un écran de démarrage statique propre en paysage, SANS commencer le gameplay.

TECHNOLOGIE / PORTABILITÉ
- HTML5 + CSS + JavaScript natif uniquement pour ce pack.
- Aucune dépendance npm, framework, bundler ou CDN.
- Aucun chemin absolu.
- Tous les liens vers assets/fichiers doivent être relatifs à la racine NYR/.
- Le projet doit pouvoir être copié plus tard sur un autre lecteur sans modification de chemins.

À CRÉER — STRICTEMENT
1. index.html
   - document HTML minimal valide ;
   - charge uniquement les fichiers locaux du projet ;
   - contient le conteneur racine de l’application ;
   - aucune logique de gameplay.

2. assets/css/main.css
   - styles globaux minimaux ;
   - écran pensé pour paysage mobile + desktop horizontal ;
   - aucune mise en page gameplay définitive ;
   - aucun framework CSS.

3. src/main.js
   - point d’entrée JavaScript minimal ;
   - initialise uniquement l’écran statique de préproduction ;
   - aucune boucle de jeu, requestAnimationFrame gameplay, timer de score, déplacement ou collision.

4. src/core/appConfig.js
   - constantes de projet non sensibles uniquement : nom NYR, slogan, statut PREPRODUCTION, version de socle ;
   - aucune donnée CJ, aucun profil, aucune URL serveur, aucun secret.

5. Écran statique de démarrage
   - afficher clairement : NYR ;
   - slogan « Absorbez. Grandissez. Survivez. » ;
   - mention discrète « Préproduction — socle technique » ;
   - utiliser si pertinent une COPIE locale d’une référence déjà présente dans assets/images/references/, sans modifier l’original ;
   - si l’image gêne la lisibilité ou complique le pack, rester sur un fond CSS simple : ne pas créer de nouvel asset.
   - aucun bouton Jouer fonctionnel ; s’il existe visuellement, il doit être absent ou clairement désactivé avec une mention de préproduction. Préférer ne pas en mettre.

6. README.md
   - mettre à jour uniquement le statut pour indiquer que PACK 1 ajoute un socle Web statique, toujours sans gameplay ;
   - conserver les liens et règles du PACK 0.

7. docs/checkpoints/CHECKPOINT_PACK_1.md
   - lister exactement les fichiers créés/modifiés ;
   - confirmer les tests réalisés ;
   - confirmer qu’aucun gameplay ni système interdit n’a été commencé ;
   - indiquer la prochaine étape comme « à définir avec CJ », sans la commencer.
